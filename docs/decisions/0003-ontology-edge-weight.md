# 0003. 온톨로지 엣지 가중치는 `corr_daily`를 쓰고, 섹터 값은 소속 종목 값의 중앙값으로 집계한다

- 상태: 채택
- 결정일: 2026-11
- 결정자: 유민, 수경
- 출처: 카톡 대화(유민→수경 질문 1차 4번, 2차 4번)

## 배경

시드 온톨로지의 엣지는 **섹터 → 매크로** 단위인데, 민감도 회귀는 **종목** 단위로 계산됩니다. 그래서 엣지 가중치로 어떤 값을 쓸지, 종목 값을 섹터 값으로 어떻게 묶을지 정해야 했습니다.

## 선택지

- **가중치 값**
  - `corr_daily`: 일별 수익률 단순회귀의 표준화 계수
  - 다중회귀 계수
- **섹터 값을 만드는 방법**
  - KRX 업종지수로 직접 회귀
  - 소속 종목 값을 섹터별로 집계
- **집계 담당**
  - 데이터 파이프라인(수경)
  - 온톨로지 쪽(유민)

## 결정

- **엣지 가중치**는 `corr_daily`(일별 수익률 단순회귀 표준화 계수)를 씁니다.
- **섹터 값**은 소속 종목의 `corr_daily` **중앙값**과 **종목 수**를 최신 as_of 기준으로 집계합니다.
  - KRX 업종지수는 무료지만, 우리가 쓰는 WICS 섹터와 분류가 달라서 쓰지 않습니다.
- **집계는 데이터 파이프라인이 뷰로 제공합니다.**
  - 일별: `sector_sensitivities`
  - 월별: `sector_monthly_correlations`
  - `sector_level`은 `l1`(대분류)과 `l2`(중분류) 두 가지이고, `is_latest`로 최신 값을 고릅니다.

```sql
select * from sector_sensitivities where is_latest and sector_level = 'l1';
select * from sector_monthly_correlations where is_latest and sector_level = 'l1';
```

## 영향

- 온톨로지는 섹터 값을 직접 계산하지 않고 위 뷰를 읽습니다.
- 소속 종목이 적은 섹터는 중앙값이 불안정할 수 있습니다. 그래서 함께 제공되는 종목 수를 보고 가중치를 신뢰할지 판단합니다.
- 요인이 없는 매크로 엣지(유가 등)에는 일별 값이 없고, 월별 상관만 있습니다 → [0002](0002-sensitivity-factors.md)
