# 0005. 벡터 저장소를 Pinecone에서 Supabase pgvector로 옮기고, 청크 ID는 내용 기준으로 만든다

- 상태: 채택
- 결정일: 2026-11
- 결정자: 수경
- 의견을 준 사람: 유민
- 출처: 카톡 대화(유민→수경 질문 1차 6번), PR #35

## 배경

리포트·뉴스 청크가 Pinecone에 있었고, 시세·재무 같은 나머지 데이터는 Supabase에 있었습니다. 저장소가 두 곳이라 종목·날짜로 함께 거르기 어려웠습니다. 또 청크를 다시 적재할 때 ID가 바뀌면, 온톨로지나 평가셋이 가리키던 청크를 잃게 됩니다.

## 결정

- 벡터 저장소를 **Supabase pgvector**로 옮깁니다. 시세·재무와 같은 DB에서 종목·날짜 조건과 함께 검색합니다.
- **청크 ID는 내용 기준**입니다. 내용이 같으면 다시 적재해도 같은 ID입니다.
- 청킹 규칙이 바뀌어 사라진 청크는 **지우지 않고 `is_active = false`**로 남깁니다. 예전 ID로 찾아도 깨지지 않게 하기 위해서입니다.
- **뉴스 ID는 원문 URL 기준**입니다.

## 현재 적재 범위

카톡 공유 시점 기준입니다.

| 문서 | 범위 |
| --- | --- |
| 리포트 | 94종목, 2026-08-07 ~ 11-06, 활성 청크 17,272개 |
| 뉴스 | 98종목, 기사 6,822건, 청크 11,576개 (최근 2주 위주) |
| 공시 | 적재 진행 중 |

## 영향

- backend가 Supabase에 직접 접속합니다. `SUPABASE_DB_URL`, `psycopg`, `UPSTAGE_API_KEY`가 필요합니다 (PR #35).
- 검색할 때는 `is_active = true`인 청크만 대상으로 해야 합니다.
- 비활성 청크가 계속 쌓이므로, 나중에 정리 기준이 필요할 수 있습니다.
- Pinecone 관련 코드와 환경변수(`PINECONE_*`)는 정리 대상입니다.
