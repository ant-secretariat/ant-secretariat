# 0007. 2종목 비교(D3)를 MVP에 포함한다

- 상태: 채택
- 결정일: 2026-11-17
- 결정자: 태은
- 의견을 준 사람: 유민 (비교 모드 설계 소유, 구현 가능성 확인 필요)
- 출처: 멀티에이전트 설계 최종 확정(10/14) 5.1, 토론 기획서 v3.0(PR #20), 11/5 범위 조정 결정

## 배경

2종목 비교를 두고 문서가 서로 달랐습니다.

- 멀티에이전트 설계 최종 확정(10/14)과 토론 기획서 v3.0은 "이번 범위 포함"입니다.
- 11/5 범위 조정 이후 PRD v1.1~v1.5, Design Doc, 기능 명세서, API 계약은 "MVP 이후"입니다.

토론 구현(PR #21~#28)이 진행 중이라 어느 쪽을 따를지 정해야 합니다.

## 선택지

- **MVP 이후 유지** — 일정 부담이 적지만, 이미 설계를 마친 비교 모드를 미룸
- **MVP 포함** — 최종 설계와 토론 기획서 v3.0을 따름. 일정과 계약 변경 부담이 생김

## 결정

**MVP에 포함합니다.** 11/5 결정 중 2종목 비교 부분을 이 ADR이 대체합니다. 자유 질의 채팅은 그대로 MVP 이후입니다.

비교 모드의 동작은 토론 기획서 v3.0을 기준으로 합니다.

- 요청은 종목 최대 2개입니다. 3개 이상이면 job을 만들지 않고 2개를 고르도록 안내합니다.
- 두 종목 모두 데이터가 있는 아젠다만 비교 축으로 씁니다(축 3개).
- 축마다 같은 질의로 두 종목을 함께 검색합니다(대칭 검색). 한쪽 근거가 없으면 그 축은 비교하지 않습니다.
- 종목마다 같은 축의 Bull·Bear를 따로 실행하고, Judge가 축별로 비교합니다.
- Judge는 "어느 쪽을 사라"가 아니라 "이 축에서 근거가 더 강한 쪽"만 판정합니다. A·B 제시 순서는 무작위로 바꿉니다.
- 한쪽이 실패하면 비교를 만들지 않고, 성공한 종목의 단일 분석으로 바꾼 뒤 이유를 알립니다.
- 비교 모드에는 시뮬레이션이 없습니다. job은 `debate_completed`에서 끝납니다.

## 영향

- **쉬워지는 것:** 최종 설계·토론 기획서와 다른 문서의 범위가 같아집니다.
- **감수하는 것:**
  - 2단계(~11/23)에 토론 단일 종목 E2E가 끝나야 비교 모드를 얹을 수 있습니다.
  - 12/6 점검일에 비교 모드가 시연 수준이 아니면 일정을 조정합니다(헌법 원칙 V).
  - 비교 결과는 종목 추천으로 읽히기 쉽습니다. 금지 표현 검사에 비교용 문구("더 좋은 종목", "A를 사세요")를 추가해야 합니다.
- **바꿔야 하는 문서·계약:**
  - PRD 4.1·4.2, Design Doc 2.2·8장, 기능 명세서 FN-DBT-01과 비교 모드 기능
  - `docs/api/openapi.yaml`: 토론 요청의 종목 목록(최대 2), 비교 결과 스키마, 설명의 11/5 결정 문구. 계약 변경이므로 FE와 토론 담당의 리뷰를 받습니다.
  - 평가: 비교셋(같은 섹터 종목 쌍)으로 축 충족률·순서 뒤집힘률·근거 대칭성을 잽니다. 비교 모드 지연 목표는 실측 후 정합니다.
