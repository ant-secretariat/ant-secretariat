# 0011. 민감도 엣지는 시장 효과를 뺀 값으로 판정하고, 종목 → 매크로 엣지는 네 가지 기준을 모두 만족할 때만 노출한다

- 상태: 채택
- 결정일: 2026-11-23
- 결정자: 유민, 수경
- 의견을 준 사람: 태은 (#29 리뷰 4·5번)
- 출처: #29 리뷰, #56, #61, #62, #64 리뷰, #67
- 대체: [0003](0003-ontology-edge-weight.md)

## 배경

[0003](0003-ontology-edge-weight.md)은 엣지 가중치로 `corr_daily`를 쓰고, 섹터 값은 소속 종목 값의 중앙값으로 하기로 했습니다. 그런데 이후 검증에서 세 가지 문제가 드러났습니다.

- **시장 효과:** 시장 효과를 빼지 않은 상관은 상당 부분 시장 전체 움직임이었습니다. 코스피 일별 수익률과 국고채 3년 변화의 상관은 −0.18입니다(#29, 11/6 기준. 11/23 기준 −0.16, #61). 시장 효과를 양쪽에서 뺀 편상관(#56)으로 다시 보니, 섹터 → 매크로 엣지 19개가 모두 기준 미달이었습니다.
- **섹터 중앙값:** 섹터 중앙값은 관련 없는 종목이 섞여 작아집니다. 반면 핵심 종목은 시장 효과를 빼도 관계가 남았습니다. 예를 들어 삼성전자 → D램 +0.218, S-Oil → 유가 +0.303입니다.
- **일별·월별 혼합:** 일별 값(같은 날 수익률 ↔ 지표 변화)과 월별 값(t월 주가 ↔ t+1월 지표 변화)이 같은 `weight` 칸에 섞여, 크기를 그대로 비교할 위험이 있었습니다(태은 #29 리뷰 4번).

## 선택지

- **판정 값**
  - 시장 효과를 빼지 않은 `corr_daily`(0003 그대로)
  - 종목 수익률과 지표 변화 양쪽에서 시장 효과를 뺀 편상관
- **엣지 단위**
  - 섹터 → 매크로만
  - 섹터 → 매크로 + 종목 → 매크로
- **다중 비교 대응**
  - 크기·신뢰구간만 보기
  - 경제적 가설과 BH 보정을 함께 보기

## 결정

**1. 매크로 민감도는 시장 효과를 뺀 값으로 판정합니다.**
- 섹터 → 매크로든 종목 → 매크로든, 시장 효과를 빼지 않은 상관으로는 노출하지 않습니다.
- 예외는 섹터 → `KOSPI`(시장 동조) 엣지입니다. 시장 자체라서 뺄 대상이 없습니다. 이 엣지는 0003대로 `corr_daily` 섹터 중앙값을 씁니다. 종목 3개 미만인 섹터는 `needs_review`(`low_n`)입니다.

**2. 종목 → 매크로 `SENSITIVE_TO`는 아래 네 가지를 모두 만족할 때만 노출합니다.**
1. 시장 효과를 뺀 값의 95% 신뢰구간이 0을 포함하지 않는다
2. |값| ≥ 0.10. 일별 표본이 약 730일이라 작은 값도 "확실"로 나오기 때문이다
3. 경제적 가설(전달 경로)이 있고 부호가 같다. 가설 없이 데이터에서만 나온 관계, 가설과 부호가 반대인 관계는 넣지 않는다
4. 가설이 있는 엣지끼리 BH 보정한 q < 0.05. 지표별 전체 종목 보정 q는 참고값으로 남긴다

**3. 가설은 값을 보기 전에 적습니다.**
- 새 엣지는 가설을 먼저 적고 값을 봅니다.
- 처음 10개(시드 v0.9, #64)는 값을 본 뒤에 가설을 붙였습니다. 그래서 `hypothesis_preregistered: false`로 두고, 목록과 가설을 2026-11-23에 고정했습니다(`hypothesis_fixed_on`). 다음 월간 계산부터는 이 목록을 새 값으로 다시 판정합니다.

**4. 매달 다시 판정하고, 떨어지면 단계적으로 내립니다.**
- 한 번 기준에서 떨어지면 `needs_review`로 바꿔 노출을 멈춥니다.
- 두 달 연속 떨어지면 `rejected`로 바꿉니다. 기각한 엣지는 지우지 않고 `rejection`(결정자·날짜·근거·수치)을 남겨, 같은 가설을 다시 넣지 않게 합니다.
- 바로 지우지 않는 이유는 토론 근거가 달마다 바뀌지 않게 하려는 것입니다.
- 판정은 시드가 합니다. 가설 목록과 기준이 시드 한곳에 있기 때문입니다. 데이터 파이프라인은 매달 입력값 표에 값을 쌓고(#58 월간 재계산), 시드는 이번 기준일과 직전 기준일의 스냅샷 CSV를 둘 다 읽어 판정합니다. 이전 CSV는 지우지 않습니다. 그래서 DB에 연속 실패 횟수 칸을 따로 두지 않습니다(#80).

**5. 일별·월별 값은 섞지 않습니다 (0003의 월별 예외).**
- 엣지에 `weight_frequency`(`daily` / `monthly`)를 두고, 주기가 다른 값끼리 크기를 비교하지 않습니다.
- 월별 엣지는 "주가가 다음 달 지표 변화를 먼저 반영하는 경향"입니다. 근거 칩(`chip_text`)에 원인처럼 쓰지 않습니다. 예: "시장 효과를 빼도 주가가 다음 달 D램 수출물가지수 변화와 같은 방향으로 움직이는 경향 (월별)".

**6. 값은 저장된 입력값 표에서 읽습니다.**
- 시드는 `ontology_sensitivity_inputs`(#67)에서 내보낸 기준일(`as_of`) 스냅샷 CSV를 읽습니다. 직접 다시 계산하거나 손으로 옮기지 않습니다(태은 #29 리뷰 5번). 시드 빌드는 DB 없이 돌아갑니다.
- 이 표는 기준일별로 쌓입니다. 다만 같은 기준일을 다시 저장하면 그 기준일 행이 새 값으로 바뀝니다. 그래서 엣지에 `as_of`와 함께 `computed_at`도 남겨, 같은 기준일 값이 다시 계산됐는지 알 수 있게 합니다.
- 섹터 집계 뷰(`sector_sensitivities`·`sector_monthly_correlations`)는 0003대로 데이터 파이프라인이 제공합니다.

**7. 계산 방법 (같은 값을 다시 내기 위해, #56에서 합의)**
- 일별: 최근 3년. 종목 수익률과 지표 변화에서 각각 코스피 일별 수익률 효과를 뺀 편상관
- 월별: 최근 최대 120개월. t월 종목 수익률과 t+1월 지표 변화의 편상관. 시장은 핵심 종목 동일가중 평균(그 종목 자신 포함)
- 신뢰구간: Fisher 변환 95% (통제 변수 1개)
- q값: 가설 엣지는 가설 엣지끼리, 참고값은 지표별 전체 종목에서 Benjamini-Hochberg. 값이 없는 가설은 p=1로 개수에 넣습니다
- 코드: `crawling/analytics/ontology_inputs.py`(계산), `ontology/seed/scripts/co_hypotheses.py`(판정)

## 영향

- 노출되는 매크로 민감도는 시드 v0.9 기준 섹터 → `KOSPI` 8개와 종목 → 매크로 10개입니다. 섹터 → 매크로(금리·환율·유가 등) 19개는 `rejected`입니다.
- 토론 근거 칩은 섹터 일반론이 아니라 종목 단위 관계를 보여 줍니다. 대신 노출 범위는 좁습니다(99종목 중 8종목).
- 매달 할 일: 새 기준일 CSV를 내보내고(`export_sensitivity_inputs.py`), 시드의 기준일·직전 기준일을 바꿔 다시 빌드합니다.
- 바꾼 코드: 시드가 스냅샷 CSV를 읽고 기준 4개·두 달 연속 규칙으로 판정(시드 v0.10, #80).
