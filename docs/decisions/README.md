## 언제 ADR을 쓰나

모든 대화를 ADR로 만들지 않습니다. 아래 중 하나에 해당하면 씁니다.

- **되돌리기 비싼 결정:** 저장소·DB 스키마·외부 서비스 선택처럼 바꾸려면 코드와 데이터를 같이 옮겨야 하는 결정
- **여러 사람의 코드에 영향을 주는 약속:** 식별자 이름, 열거형 값, 단위, API 계약
- **나중에 누군가 "왜 이렇게 했지?"라고 물을 결정:** 다른 선택지를 버린 이유가 중요한 경우

이 기준에 걸리지 않는 작은 결정은 결정 목록에 한 줄만 적고, 링크 칸은 PR이나 이슈 번호로 대신합니다.

## 카톡에서 결정이 났을 때

카톡은 논의하는 곳이고, 기록은 저장소에 남깁니다. 대화가 흩어지지 않게 다음 순서를 지킵니다.

1. **카톡에서 결정 문장을 남깁니다.** 합의가 되면 한 사람이 `[결정] ...` 형식으로 한 줄 요약을 보냅니다. 다른 사람이 동의 표시를 하면 결정으로 봅니다.
2. **질문한 사람이 이틀 안에 기록합니다.**
   - ADR 기준에 해당하면 새 ADR 파일을, 아니면 결정 목록 한 줄을 PR로 올립니다.
   - 결정자 전원을 리뷰어로 지정하고, PR 승인을 최종 합의로 봅니다.
3. **매주 한 번 빠진 결정을 확인합니다.** 주간 회의 처음 5분에 지난주 카톡의 `[결정]` 메시지를 훑고, 기록되지 않은 것을 담당자에게 넘깁니다.

**공개 저장소라서 주의합니다.**
- 카톡 원문을 그대로 붙여 넣지 않습니다.
- 개인 정보와 비밀값을 적지 않습니다.
- 결정과 이유만 요약합니다.

## ADR 작성과 상태

1. [template.md](template.md)를 복사해 `NNNN-짧은-영문-제목.md`로 저장합니다. 번호는 다음 순번입니다.
2. 결정 목록 표에 한 줄을 추가합니다.
3. PR로 올리고 결정자가 승인하면 머지합니다.

| 상태 | 뜻 |
| --- | --- |
| 제안 | PR로 올라와 검토 중 |
| 채택 | 합의되어 따르는 중 |
| 대체됨 | 새 ADR로 바뀜. 새 ADR 번호를 적어 둡니다 |
| 폐기 | 더 이상 따르지 않음 |

- **채택된 ADR은 고치지 않습니다.** 결정이 바뀌면 새 ADR을 쓰고, 이전 ADR의 상태를 `대체됨 (→ NNNN)`으로만 바꿉니다. 그래야 결정이 바뀐 경위가 남습니다 (AWS ADR 가이드).
- 오타나 링크 수정은 예외입니다.

## 왜 이 방식인가

| 방식 | 장점 | 우리 팀에 맞지 않는 점 |
| --- | --- | --- |
| **저장소의 ADR + 결정 목록 (선택)** | 코드 옆에 있어 PR 리뷰로 합의하고, 변경 이력이 남고, AI 에이전트가 읽을 수 있음 | 기록하는 습관이 필요함 → 위의 "카톡에서 결정이 났을 때" 규칙으로 보완 |
| 카톡 공지·노트 | 바로 쓸 수 있음 | 검색과 변경 이력이 약하고, 코드와 연결되지 않음 |
| Notion 결정 DB | 표 보기·필터가 편함 | 코드와 떨어져 있어 PR에서 참조하기 어렵고, 에이전트가 읽지 못함 |
| 채팅 자동 수집 도구(Slack 앱 등) | 기록 부담이 적음 | 카톡은 연동이 어렵고 유료가 많음 |
